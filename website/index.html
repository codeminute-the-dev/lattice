In plain terms

What Lattice actually is

Lattice is a cryptocurrency. Like Bitcoin, nobody runs it: a network of computers keeps a shared ledger, and new coins go to whoever contributes computing power.

The difference is what that computing power does. Bitcoin miners compute SHA-256 hashes — a deliberate lottery, useful to nobody outside the network. Lattice miners multiply matrices, then attach a zero-knowledge proof that they did the multiplication correctly. Anyone can check the proof in milliseconds without redoing the work.

An honest caveat. The matrices miners multiply are generated by the protocol, not supplied by customers with problems to solve. Calling it “useful work” describes the kind of computation, not a claim that someone is getting their homework done. What it buys is a proof-of-work whose hardware and arithmetic sit close to genuinely useful computing, rather than a function designed to be useless on purpose.

The consensus machinery is inherited unchanged from Pearl, which Lattice forks. What Lattice changes is the economics.

Emission

The reward resets. On a schedule anyone can check.

Every block pays a reward. It starts at exactly 2 LATT and decays smoothly — no halvings, no cliffs. After roughly four years the schedule resets: the reward jumps back to 2 LATT and the curve starts over. This repeats indefinitely. Scrub the chart above to see any point on it.

Why reset at all?

A decaying reward eventually approaches zero, and mining stops paying for the security it provides. Bitcoin's answer is to assume transaction fees will replace the subsidy. That might work. It is also an untested bet on an economy that doesn't exist yet.

Lattice doesn't take that bet. The curve restarts on a fixed schedule, so miners in year twenty are paid about what miners in year one were paid. Turn on Compare with halving above to see the two side by side: by year twelve a halving schedule pays a quarter of where it started, while Lattice is back at 2 LATT.

The tradeoff, stated plainly. This makes Lattice mildly inflationary permanently. There is no maximum supply. If you want a hard-capped asset, Lattice is not it. What it offers instead is that the inflation is completely predictable: every reward at every future height is fixed at launch and computable by anyone, offline, today.

Three guarantees

Nobody can change it

The constants are compiled into the node. No admin key, no governance vote, no config file. Changing them means shipping a different binary that every operator must choose to run.

Resets never touch your coins

A reset changes the reward of future blocks only. Balances and already-mined supply are untouched. There is no rebasing and no dilution event.

You can compute it yourself

Resets land at block 3,153,601, then 6,307,201, and so on forever. No chain data needed — just arithmetic on published constants.

Full derivation, including the exact formula and every constant: docs/emission.md.

Mining

Solo mining, without a pool

Pools exist because block rewards are lumpy. If blocks are rare and rewards large, a small miner can go months without income even while earning a fair average. Pools smooth that out — and concentrate block production in a few operators.

Lattice attacks the lumpiness instead: 40-second blocks at 2 LATT each, about 2,160 blocks a day. Rewards arrive steadily rather than as an annual windfall.

Get started

Build the node and tools:

# needs Go 1.26+, Rust, a C compiler
git clone https://github.com/codeminute-the-dev/lattice
cd lattice && task build:blockchain

Create a wallet and take an address:

cd bin && ./latwalletcli   # walks you through setup

Start a node on simnet, mining to your address:

./bin/latticed --simnet \
  --rpcuser=rpcuser --rpcpass=rpcpass \
  --miningaddr=<your-address> --txindex

Mine some blocks and watch the schedule move:

./bin/latctl --simnet -u rpcuser -P rpcpass generate 200
./bin/latctl --simnet -u rpcuser -P rpcpass getnextreset

# reward at height 200: 1.71599906 LATT
# reward at height 201: 2.00000000 LATT   <- reset

Simnet uses a 200-block epoch so a full reset takes minutes instead of years. Step-by-step guide: docs/solo-mining.md.

Wallet

Holding and sending LATT

latwallet is the wallet daemon; latwalletcli is an interactive terminal client that configures it for you. Addresses look like lat1p4cnr4uwp… on mainnet and tlat1… on testnet. 

# create a wallet — record the seed phrase offline
./bin/latwallet -u rpcuser -P rpcpass --create

# start it, then get an address to receive at
./bin/latwallet -u rpcuser -P rpcpass &
./bin/latctl -u rpcuser -P rpcpass -s https://localhost:44207 getnewaddress

# check your balance / send some LATT
./bin/latctl -u rpcuser -P rpcpass -s https://localhost:44207 getbalance
./bin/latctl -u rpcuser -P rpcpass -s https://localhost:44207 sendtoaddress <addr> 1.5

Your seed phrase is the only way to recover the wallet. Write it down on paper. Nobody — not the maintainers, not a support address — can restore it for you.

Mined coins need 100 confirmations before they can be spent, about 67 minutes. Transaction fees have a near-zero floor; you can pay more for priority, but ordinary transfers cost a rounding error.

Fair launch

No premine. Verify it yourself.

The genesis block created zero coins. Its single output pays 0 to an OP_RETURN script, which is provably unspendable by anyone including whoever wrote it. There is no founder allocation, no developer tax, no treasury, and no pre-mined stash.

Every LATT that will ever exist is mined after block zero, by someone doing the work.

You don't have to believe any of that. Check it:

# rebuild the genesis blocks from source and diff against what ships
go run ./node/cmd/gengenesis > /tmp/genesis.go
diff /tmp/genesis.go node/chaincfg/genesis.go

# the consensus tests that enforce it
go test ./node/chaincfg/  -run TestGenesisHasNoPremine -v
go test ./node/blockchain/ -run TestGenesisMintsNothing -v

The genesis coinbase also embeds the hash of Bitcoin block #963094. That hash could not have been known before that block was mined, which is evidence the chain wasn't quietly started early and mined in private.

Where the project actually stands. Lattice is alpha software at version 0.1.0. A single mainnet node is running — the one feeding the panel above — but the chain is still at height 0, because mining needs the GPU miner and nobody has pointed one at it. There are no other peers, the DNS seeds don't resolve yet, and LATT has no price because there is nowhere to trade it and nothing to trade. Run it on simnet, read the code, tell us what's wrong with it. Please don't treat it as an investment — there is nothing to invest in yet.

Hardware

On ASICs, honestly

Lattice does not claim to be ASIC-resistant. That claim is rarely true for long, and the history of “ASIC-resistant” algorithms is mostly a history of ASICs turning up later while the claim stayed on the website.

There's also a reason not to fight too hard: the work function is deliberately shaped so ordinary ML accelerators are good at it. A GPU is already a matrix-multiplication ASIC. The worry isn't specialised hardware existing — it's mining power concentrating in hardware nobody else can buy.

So the mitigation is procedural rather than cryptographic. The work function's shape parameters live in one version-tagged file, so if retuning is ever justified, the change is a small diff a reviewer can read in one sitting instead of a rewrite. Adoption happens by operators upgrading — there's no key that forces it. The full policy spells out what would trigger a proposal and how one would proceed.
